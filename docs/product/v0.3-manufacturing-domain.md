# v0.3 Manufacturing Domain — Product Requirements

**Status: In Progress**

## Problem

The application has a working conversation flow and minimal LangGraph
orchestration, but it cannot yet ground manufacturing questions in structured
records. Industrial wording in the interface must not be mistaken for
production-backed analysis.

This milestone establishes a small, deterministic manufacturing domain before
tools or model interpretation are introduced.

## Intended user

The primary user is a developer or reviewer examining how an industrial AI
agent separates recorded facts, deterministic calculations, and later model
interpretation. The milestone does not serve a live factory operator.

## Approved first scenario

The first scenario uses fictional equipment `AOI-WAFER-01`, Production Lot
`LOT-DEMO-001`, and wafers as the counted unit. Inspection results are stable
from 08:00 through 14:59 UTC. After 15:00 UTC, Yield Rate declines while the
fictional `edge-chip` Defect Count rises and an `OPTICAL-SIGNAL-LOW` Alarm Event
co-occurs.

The scenario records correlation only. It does not identify or imply a root
cause.

## Scope

- Define shared language for Equipment, Production Lot, Wafer, Inspection
  Record, Defect Count, Alarm Event, Time Range, Yield Rate, and Production
  Summary.
- Validate non-negative counts, inspection-count conservation, UTC timestamps,
  and Defect Counts that do not exceed failed wafers.
- Use half-open Time Ranges: the start is included and the end is excluded.
- Aggregate inspected, passed, and failed wafers, Yield Rate, Defect Counts, and
  overlapping Alarm Events for one Equipment and Time Range.
- Return an explicit empty result when no Inspection Records match.
- Store the first scenario as independently created, reproducible synthetic
  data.

## Exclusions

- API endpoints, database persistence, LangGraph tools, and frontend surfaces
- LLM interpretation or causal inference
- live equipment connectivity or production data
- authentication, authorization, deployment, or operational monitoring
- confirmed equipment-status and throughput semantics until separately
  approved

## Evidence boundary

Inspection Records and Alarm Events are recorded synthetic facts. Yield Rate
and aggregated Defect Counts are deterministic calculations. Temporal
co-occurrence is not evidence of causation. Missing Inspection Records must not
be converted into a production value or equipment condition.

## Acceptance criteria

- Public domain types reject invalid time and numeric boundaries.
- Production Summary includes only records for the requested Equipment and
  half-open Time Range.
- Yield Rate equals passed wafers divided by inspected wafers when the inspected
  count is greater than zero.
- An empty result contains zero counts, unavailable Yield Rate, and an explicit
  limitation while retaining independently recorded overlapping alarms.
- Defect aggregation and ordering are deterministic.
- The AOI dataset loads through the same public domain types and contains no
  causal claim.
- Focused tests, the complete API suite, Ruff, package build, and JSON parsing
  pass.

## Open decisions

- Define whether Equipment Status is an observed event, a calculated state, or
  both.
- Decide whether throughput is required for v0.3 or should enter with v0.4
  production-data tools.
